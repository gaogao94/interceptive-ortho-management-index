# 阻断性正畸管理指数（IOMI）· 早矫管理体检

> **Interceptive Orthodontic Management Index** — 一个让 AI 智能体执行的**诊断问卷 skill**：用**一题一问**的方式访谈早矫（儿童青少年早期矫治）机构负责人，量化判断这家机构"早矫做得好不好、管得住管不住"，再按命中的缺口给出可执行的改进动作。

**关于名字**：早矫在正畸学术文献里的规范英文术语是 **interceptive orthodontics**（阻断性正畸），见美国国家医学图书馆的规范主题词表 [MeSH D009972](https://meshb.nlm.nih.gov/record/ui?ui=D009972 "Orthodontics, Interceptive")（树号 `E06.658.641`，与 `Orthodontics, Preventive`、`Orthodontics, Corrective` 并列）。日常也写作 `early orthodontic treatment`；美国正畸协会（AAO）的口径是 [Phase 1 treatment](https://aaoinfo.org/whats-trending/6-facts-about-two-phase-treatment/)。本仓库采用前者，因为它是索引与检索里的标准词。

它的立场一句话：**看得见，才管得住。**

早矫这门生意，管得好是利润的倍增器，管不好是定时炸弹。差别通常不在营销，而在三件事：有没有标准、有没有留痕、有没有一本明白的账。

- **主要用户**：门诊老板、门诊管理者（店长 / 医疗总监）、正畸学科负责人。
- **前置要求**：不需要懂统计，不需要先上系统。答不出来本身就是重要信息。
- **不做什么**：不诊断患者、不给临床建议、不做法律或会计意见。

## 给其他 Agent 的一句话用法

按 https://github.com/gaogao94/interceptive-ortho-management-index 里的 SKILL.md 给我做一次早矫管理体检。

（这句话可直接粘给 Claude Code、Codex 或任何能读网页/仓库的智能体，它自己会去取 `SKILL.md` 与 `reference/`。）

**句子里不需要写"每题给选项""别给我看分数""24 题都要答完"这类要求。** 那些是 skill 的职责，已经在 `SKILL.md` 里写死了：

| 要求 | 固化在 |
|---|---|
| 每题给选项、不让受访者打字 | `SKILL.md` 第 2 步「一题一问，而且是**选项题**」＋发送格式示例 |
| 选项里不出现分数 | `SKILL.md` 第 2 步「三条硬规则」第 1 条「绝不暴露分数」 |
| 24 题缺一题就不出报告 | `SKILL.md` 第 2 步与第 2.5 步；`tools/render_report.py` 另有 exit 2 硬门禁 |
| 每题的第五项是「不知道 / 没想过」 | `reference/question-bank.md` 每题选项 |
| 追问也给选项、一题最多追一次 | `SKILL.md` 第 2.6 步 |

prompt 里重复这些只在一种情况下有用：**你怀疑对方 agent 不会读完 `SKILL.md`**。
默认不必写 —— 要求写在两处，改的时候就会漏改一处。

## 一次运行会发生什么

| 环节 | 内容 |
|---|---|
| 访谈 | 4 个维度、24 道题（A1–A6 / B1–B6 / C1–C6 / D1–D6），**助手一次只发一题，每题带选项** |
| 时长 | 约 15–25 分钟，一题选一个选项 |
| 评分 | 每题 0 / 1 / 2 / 3 分；维度满分 18（6 题 × 3 分）；总分 = 四个维度之和 ÷ 72 × 100 |
| 定级 | L1 无标准 / L2 刚起步 / L3 有体系 / L4 能自转；**命中红线会降级封顶** |
| 产出 | 一份《早矫管理体检报告》：等级、红线诊断、逐题证据、改进动作、90 天路线图、K1–K8 指标表 |
| 呈现 | 同一份报告三种形态：**Markdown**（对话里直接读）、**shadcn 风格单页 HTML**（点开/转发/打印）、**PNG 图片**（发微信、贴 PPT） |

报告默认同时产出一页 HTML——它是给老板、合伙人、门店管理层看的东西，一页能点开、能转发的页面比一段聊天记录有用得多。三种形态内容一致，只是呈现方式不同。

**交互形式是选项题，不是自由文本。** 每一题给出 4 档描述 + 一个「不知道 / 没想过」，回复数字即可；只有机构名称、门店数这类事实性问题要打字。**选项里不会出现分数**——分数是内部映射，露出来受访者就会去猜哪个分高，答案立刻失真。

访谈纪律（这也是它和"发一张问卷"的区别）：

- 一次只发一题（题干 + 选项 1–5）；开场会说清"一共 24 题、大约 15–25 分钟"，但**不预告后面的题目内容或方向**，避免诱导；
- **没有"跳过"这个选项**：每题的第五项「不知道 / 没想过」就是出口，选它判 0 分；但**跳题就不出报告**——24 题缺一题都不行；
- 答得含糊或答了题外话，助手会把它归到最接近的选项并念回来确认，不会替你另起一个判断；
- 必要时追问同一题（比如"这个数是算出来的还是估的"），**追问也给选项**，一题最多追一次；
- 每答完一题落一条账：`题号 | 你选的项与原话 | 判分 | 依据`；
- 指标答不出来不扣人，但要如实记成"未知"，并写清这个数该从哪张报表取。

**这 24 题必须一次问完。** 没有"批量模式"——一次把 24 题全发出去，受访者会先把整张表扫一遍再回来凑答案，诊断质量会掉到没有意义的程度。答到一半要停也可以，前面的记录会保留，但报告要等 24 题答齐才出。

## 最短用法示例

下面是真实节奏的摘录（**机构与数字均为虚构，仅示意**）：

> **用户**：我们是××口腔门诊，3 名正畸医生，想做一次早矫管理的体检。
>
> **助手**：好。这是一次机构管理体检，大概 15–25 分钟，一共 24 个问题，我一次只发一个，每题给几个选项，你选一个就行。确实不知道就选「不知道 / 没想过」，那也是答案；但别跳题，跳过一题报告就出不来。
>
> 【1/24】现在你们在册的早矫病例一共多少例？其中有多少例已经超过当初计划的结束时间？
>
> 1. 随时能调出两个数，还能按医生、按门店分开看
> 2. 两个数都能查出来，但需要临时统计，花半天到一天
> 3. 只有一个数拿得到，另一个查不到
> 4. 两个都说不清，要靠问医生、翻本子
> 5. 不知道 / 没想过
>
> 回复数字即可。
>
> **用户**：4 吧……在册一百多例，超期真没统计过，得让医助去数。
>
> **助手**：好，记第 4 项。你补的这句我也记下了——"在册一百多例，超期没统计过"，报告里会作为你的原话留底。
>
> 【2/24】你们对早矫有明确的结束周期标准吗？比如一个病例计划多久结束、平均延期几个月算正常？
>
> 1. 有分类型的周期标准，延期被持续统计，并进入医生反馈与排程
> 2. 有书面周期标准，也统计过平均延期，但没和医生考核或排程挂钩
> 3. 口头上有大概印象，但没有写下来，也没算过延期
> 4. 没有周期标准，也从未算过延期情况
> 5. 不知道 / 没想过
>
> **用户**：3。一般跟家长说一年半到两年，但没写下来，也没算过平均延期。
>
> **助手**：记第 3 项。补充问一下：「18 个月」这个数是算出来的，还是大概估的？
>
> 1. 有测算依据，能说出怎么来的
> 2. 是经验估算，没有测算过程
> 3. 说不好
>
> **用户**：2，就是经验。

三条要点：

- 助手每条消息**只发一道题**（A1 的两个数、A2 的周期标准），发完停下等回复，不预告下一题。
- 题干下面**只有 1–5，没有分数**。分数是内部映射：选项 1 → 3 分，选项 4 → 0 分，选项 5 → 0 分。
- 受访者选了选项之后如果还补了话，助手会把**选项号**和**原话**都记下来——报告里"受访者关键原话"那一列就是靠这个来的。

想看完整的一次运行（24 题判分账目、红线降级、动作优先序与报告全文），见 [`docs/example-run.md`](docs/example-run.md)。

## 诊断模型速览

### 四个维度（各 6 题，满分 18）

| 维度 | 管什么 |
|---|---|
| **A · 标准与分级** | 病例底数、过程管理标准、难度分级、医生能力分级、承接容量 |
| **B · 方案审核与结案** | 方案审、审核内容、阶段目标、结束复核、终点定义、偏离处理 |
| **C · 记录与过程数据** | 挂号留痕、记录字段、效率指标入报表、重启与延期统计、进度地图、成本归属 |
| **D · 财务与激励** | 预收款确认、提成发放节奏、负债与产能匹配、结束质量挂钩绩效、单例毛利、就诊次单价 |

### 等级 L1–L4

| 等级 | 分数区间 | 名称 | 一句话特征 |
|---|---|---|---|
| L1 | 0–30 | 无标准 | 没有标准、没有计划时长、没有账，全凭医生个人 |
| L2 | 31–55 | 刚起步 | 有零散做法，但不系统、不留痕、不可复算 |
| L3 | 56–80 | 有体系 | 有标准并能执行、数据可查，收尾复核还有缺口 |
| L4 | 81–100 | 能自转 | 标准、审核、留痕、复核、激励、财务全部到位 |

### 四条红线 R1–R4（命中即封顶）

| 红线 | 判据 | 一句话 |
|---|---|---|
| R1 | 在册早矫病例底数看不见（A1 判 0 或 1） | 看不见 |
| R2 | 没有量化周期标准，也拿不出延期数据（A2 判 0/1，且答完 A2 仍给不出可核数字） | 没有靶子 |
| R3 | 结束无书面复核（B4 判 0 或 1——只有口头确认也算命中） | 没人核 |
| R4 | 预收矫正款在收款当月 / 次月一次性发放全额提成（D2 判 0） | 钱先走了 |

命中任意一条，**等级**封顶到 L2；命中两条及以上，封顶 **L1**，并在报告里单列（总分栏仍显示原分）。判定全部锚在具体题号与分档上，访谈当场就能判。完整判据表见 [`SKILL.md`](SKILL.md) 的「红线」一节。

### 六个动作 ACT-1 – ACT-6

| 动作 | 名称 | 覆盖题号 |
|---|---|---|
| ACT-1 | 建标准、分级、看底数 | A1 A2 A3 A4 A5 A6 B1 B2 |
| ACT-2 | 结果要核 | B4 B5 C4 D4 |
| ACT-3 | 阶段目标要跟 | B3 B6 C5 |
| ACT-4 | 每次就诊都留痕 | C1 C2 C3 C6 |
| ACT-5 | 提成按阶段发 | D2 D4 |
| ACT-6 | 财务的账要算明白 | D1 D3 D5 D6 |

报告**只输出你命中的动作**，不会把六个动作全文倒给你；进不进报告由"缺口够不够大"决定（覆盖题号均分 < 2，或其中出现 0 分），**不挂红线的动作也可能进**。顺序是**档位优先**：`P0`（挂红线的动作里两周内能落地的：ACT-1、ACT-2）→ `P1`（其余挂红线的动作：ACT-5、ACT-6）→ `P2`（不挂红线的：ACT-3、ACT-4），同档按缺口大小排。档位表与排序规则见 [`SKILL.md`](SKILL.md) 的「动作优先序」，落地步骤见 [`reference/playbook.md`](reference/playbook.md)。

### 八个关键指标 K1–K8

| 指标 | 是什么 | 主要来自 |
|---|---|---|
| K1 | 在册早矫病例数 | A1 |
| K2 | 超计划时长（延期）病例占比 | A1 B5 |
| K3 | 计划结束时长（月）与实际结束时长（月） | A2 |
| K4 | 平均延期月数 | A2 B5 |
| K5 | 计划外复诊率（托槽脱落、钢丝扎嘴等） | C2 C3 |
| K6 | 平均椅位占用时长、每例就诊次数 | C3 |
| K7 | 重启率 / 二次治疗率 | C4 |
| K8 | 单例就诊次单价（收入 ÷ 就诊次数） | D6（分母来自 C3） |

**未知即结论**：任何一个指标你答不出来，报告不会估一个数糊过去，而是写"未知"并告诉你哪张报表、哪个字段能查出来。指标不是为了好看，是为了让"拖得越久越不赚钱"从感觉变成算式。

## 可选：导出成 Excel（指标地图 / 填答表）

```bash
python tools/build_metrics_workbook.py 门诊早矫管理指标地图.xlsx
```

产出 **5 张表**，版式对齐常见的口腔经营指标地图（标题行合并居中 + 三栏分组 + 分组色块 + 细边框）：

| 工作表 | 内容 |
|---|---|
| 指标地图总览 | 四个维度 / 四档等级 / 红线封顶规则 / 用法与分值映射 |
| A-1 标准与分级 | A1–A6 每题一行：题号、题干、**五个选项**、判分锚点与红线提示 |
| A-2 方案审核与结案 | B1–B6 |
| A-3 记录与过程数据 | C1–C6 |
| A-4 财务与激励 | D1–D6 |

四张维度表名带维度全名（`A-1 标准与分级` 而不是 `A 维度`），一眼看得出每张表管什么。

**每张维度表都是可填答并自动算分的**：在「选择」列填 1–5（带下拉校验），
右侧「得分」列自动出分；表底有小计与维度分（合计 ÷ 18 × 100）。
分值映射：选项 1 → 3 分、2 → 2 分、3 → 1 分、4 → 0 分、5「不知道 / 没想过」→ 0 分。

两个脚本配套使用，都过 LibreOffice 重算引擎：

```bash
python tools/test_metrics_workbook.py 门诊早矫管理指标地图.xlsx   # 公式：逐题 24 + 小计 4 + 维度分 4
python tools/check_row_heights.py     门诊早矫管理指标地图.xlsx   # 行高：每行都设了且够高
```

公式验收用康桥样例的判分账目作输入，与报告数值逐项一致（维度 33/28/39/17、总分 29）。

**行高是算出来的，不靠 Excel 自动撑行。** 程序生成的工作簿里自动行高往往不生效，
`wrap_text` 的长文本会被直接裁掉 —— 所以 `build_metrics_workbook.py` 里有个
`calc_row_height()` 按「字符数 ÷ 列宽」估行数再定高，`check_row_heights.py` 用同一套
算法反向核对（中文按 1.0 字/列宽单位保守估，宁高不矮）。

导出物**不随仓库分发**（`.gitignore` 忽略 `*.xlsx`）：它是一次性产物，脚本才是源头。

## 可选：用一张 CSV 自查数据

如果机构能导出一张脱敏病例表，`tools/early_ortho_metrics.py` 可以离线帮你把 K1、K2、K3、K4、K6、K7、K8 里能算的部分先算出来（纯 Python 标准库，不联网、不上传）。

```bash
python tools/early_ortho_metrics.py --csv cases.csv \
    --status-active 在治 --status-closed 已结案 --as-of 2026-09-30
```

表头不是上面那套英文列名也没关系，用 `--col-*` 映射：

```bash
python tools/early_ortho_metrics.py --csv 导出.csv \
    --col-case-id 病例号 --col-plan-end-date 计划结束日期 --col-fee 实收金额
```

它最重要的行为是**不肯猜数**：缺列、整列为空、单元格解析不出来，都会打印一行

```
未知（缺少字段: plan_end_date，建议从 方案或病例详情 · 计划结束日期 导出）
```

而不是用 0 顶替。它也不做医疗判断——它只是一张 CSV 的算术汇总。`--help` 里有全部参数，脚本末尾附了一份虚构样例 CSV。

⚠️ 用之前请务必自行脱敏：**不要**把患者姓名、手机号、身份证号导进 CSV，也不要提交进仓库。

## 关于这个 skill 的维护

本仓库由作者维护，**修改由作者统一发布**。这不是不欢迎反馈——发现错误、有改进
想法、想补一个维度或调整判据，都欢迎开 issue 说明，作者会看、会回，采纳后由作者
改到仓库里。这样做的目的是让公开版本只有一个权威来源：使用者拿到的永远是一致的
题库与判据，不会因为版本分叉而算出两套分数。

这也是本仓库采用 CC BY-NC-ND 而不是 MIT 的原因：**CC BY-NC-ND 让"公开可读可用"、
"不允许分叉出改版"、"不允许拿它对外收费"这三件事同时成立**，而 MIT 允许任何人发布
一个改了判据的副本，也允许把它打包成收费产品。

作者改的时候，有三条最容易踩：

1. **编号是契约**：四维度、L1–L4、R1–R4、ACT-1–ACT-6、K1–K8 的名称与编号在仓库内唯一。改一处，`SKILL.md`、`reference/`、`docs/`、README 要同步。
2. **判据与题号必须对得上**：每个 ACT 的"什么时候算做到"里用到的题号，必须出现在该 ACT 的覆盖列表里；六个动作的覆盖题号并集必须恰好是 24 题。
3. **改完必须复算样例**：[`docs/example-run.md`](docs/example-run.md) 是自测样例，不是装饰。任何改动都要重算它的维度分、总分、红线结论与优先序，并核对正文每一个数字——样例与规则对不上，等于规则没有被验证过。
